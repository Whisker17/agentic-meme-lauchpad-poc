0五分钟版本#

这个系统做什么？为什么敢让一个 AI 动钱？

  • 你在 Telegram 里用中文跟一个 OpenClaw agent 说话，它替你在 Mantle Sepolia 的 meme 发射台上查余额、发币、买卖、打新、领手续费。没有前端。
  • 你的钱包是一个普通 EOA，通过 EIP-7702 原地升级成 Calibur 智能账户：地址不变，根密钥（root key）一直在你自己的终端里。
  • agent 只拿到一把会话密钥（session key）。链上的 AgentPolicyHook 只放行 5 个函数，MockUSD 花费有总额和每日上限，只能卖它自己买到的币；24 小时后过期，你随时可以撤销。
  • 每笔交易都不用 gas：代付服务（sponsor）的 relayer 付 MNT，你的账户和 agent 都可以是 0 MNT。
  • 打新由一个确定性的 autopilot daemon 执行，LLM 只写策略、启停和汇报；策略必须等你回一句“是”才启动。
  • 交易权限的强制边界只有链上这一层：skill 里的规则只约束守规矩的模型。容器是凭据隔离边界：它不让 agent 拿到 root key 和 root home，但不限制 agent 已经拿到的 session key 能做什么。这是 POC：合约未审计，只在测试网。

第一部分

原理

先分开讲两个项目，再把它们合起来。第 1 节是 7702 SDK：它给 agent 一个受限、可撤销、不用付 gas 的智能账户。第 2 节是 meme 发射台：它在 SDK 之上加了合约、库、CLI、autopilot 和 OpenClaw agent。第 3 节把两者拼起来，看一笔交易怎样穿过所有组件。

17702 SDK：给 agent 一个受限的智能账户#

7702 SDK 是怎么设计的？一次授权、一次执行在链上和链下各发生了什么？我们怎样用它？

mantle-7702-sdk 是一个独立的仓库，以 @0xwh1sker/mantle-aa-sdk、-cli、-sponsor 三个包发布在 npm 上。本项目只把它当依赖用（锁在 ~0.1.5），从不修改、复制或 fork 它的代码。它解决的问题是：怎样让一个不可信的 AI agent 动用一个账户里的钱，而损失有上限、随时能收回。它的答案由四个能力组成：

  1. 原地升级人的普通钱包（EOA）通过 EIP-7702 升级成 Calibur 智能账户。地址、余额、私钥都不变。
  2. session key人给每个 agent 授一把自己的密钥，不是 admin，24 小时过期，随时可撤销。
  3. 链上 policy这把 key 能调哪些函数、能花多少钱，由链上的 AgentPolicyHook 在执行时检查，不靠链下代码自觉。
  4. gasless升级、授权、执行、撤销，每一步都由 sponsor 付 gas。人和 agent 都可以一个 MNT 都没有。

设计

三个包，两个合约#

SDK 分链下和链上两半。链下三个包各有各的用户：人用 CLI，程序（比如本项目的 meme-sdk）用 TypeScript 库，运营方跑 sponsor。链上只有一个合约是 SDK 自己写的，就是 AgentPolicyHook；账户本身用的是 Uniswap 现成的 Calibur。

四方的信任程度完全不同，SDK 的每个设计都从这张表推出来：

谁信任吗推出来的设计
root key（人）完全信任root 就是账户本身（keyHash = 0），admin，不受 hook 约束。升级、授权、撤销、转账只有它能做。
session key（agent）不信任每一条限制都必须在执行时于链上成立。SDK 本地的检查只是为了早失败、省 gas，不算数。
sponsor信任它的钱和可用性它不是安全边界：agent 可以绕开它，自己付 gas 直接调账户，链上规则照样生效。
发射台（受信 spender）由人核实后写进 policyhook 验证不了发射台的行为，所以发射台必须满足一份接口约定：无 owner、只从调用者拉钱、卖出要么足额要么回滚。

由此得出 SDK 的核心承诺：一把被攻破的 session key，造成的报价资产净流出不超过它的额度（按成本算）；只能卖它自己买到的数量；改不了 policy，撤销后回不来。持仓的市值它不保证，详见 第 5 节。（AA-DESIGN §4.0）

为什么

三把钥匙分开，是为了让每一种泄露的后果都有界。agent 天生不可信（它读的是模型输出，而模型读的是网上的文字），所以它拿的是一把权限最小、可以撤销的钥匙；能动全部资金的 root key 只留在人手里。（AA-DESIGN Q1、§4.0；本仓库 D9）

工作原理

一个账户在 SDK 里的一生只有三类操作，下面四小节按这个顺序展开：

  1. 升级 + 首次授权root 签 · 一笔 type-4 交易UNDELEGATED → DELEGATED → INITIALIZED，同时注册第一把 session key 并写入它的 policy
  2. agent 执行session key 签 · 每次一笔本地模拟 → 签批次 → sponsor 代付 → Calibur 验签 → hook 逐个调用检查
  3. 撤销 / panicroot 签 · 一笔Calibur 删 key、hook 立墓碑、授权清零。墓碑永久，同一把 key 永远回不来

EIP-7702：原地升级，地址不变#

EIP-7702 让一个 EOA 把自己的代码“委托”给一个合约实现。委托之后，这个地址上跑的是合约代码，但地址、余额、私钥都还是原来的。这里的实现是 Uniswap 的 Calibur v1.1.0（部署产物叫 CaliburEntry）。

升级只需要一笔 type-4 交易，由 sponsor 代付 gas。交易里带两样东西：root key 签的 7702 授权，和一个初始化批次。批次里顺手注册第一把 session key，并在 AgentPolicyHook 上写入它的 policy。

升级之后，Calibur 里有两类 key。root key（keyHash = 0）是 admin，不受 hook 约束；session key 不是 admin，带过期时间，并且绑定了 AgentPolicyHook。Calibur 每执行 session key 批次里的一个调用，都会在调用前后各调一次 hook。

坑

7702 授权在执行之前就生效。初始化批次失败时，委托不会撤销，账户停在 DELEGATED 状态。SDK 的状态机是 UNDELEGATED → DELEGATED → INITIALIZED，重试前会重新读链上状态，所以重新跑一次 account init 就行。

逐项读一遍，就知道 agent 的边界在哪：

  • 白名单只有 5 个 (合约, 函数)。MockUSD 上只允许 approve，所以没有 transfer，钱转不出去。
  • 额度按 MockUSD 余额的净减少计：总共 100，每 86400 秒 50。收进来的钱不会把用掉的额度还回去。MNT 额度是 0。
  • approve 的 spender 只能是发射台，数额不能超过剩余额度。
  • 买卖的收款人必须是账户本身，deadline 必须落在 [now, now + 600 s]。
  • 卖的数量不能超过这把 key 的库存（inventory）。inventory 是 hook 记的账：这把 key 通过 LAUNCHPAD_BUY 买进来多少，它就最多能卖多少。
  • createToken 和 claimCreatorFees 是 NONE：只查白名单，不查参数。发币不付钱也不给调用者代币，领手续费是钱流进账户，两者都伤不到账户。

坑

inventory 按 key 记，不按账户记。你自己转进账户的代币、别的 session 买的代币，这把 key 都卖不了（exit 12）。portfolio 里 balance 和 inventory 是两个数，卖之前看后者。

gasless：relayer 代付#

session key 签的不是一笔普通交易，而是 Calibur 的 SignedBatchedCall：一组调用，加一个 2 分钟的截止时间，并且指定 executor 是 sponsor 的 relayer 地址。AA SDK 把它连同一个请求签名发给 sponsor 的 sponsor_relay。sponsor 验证请求、查 allowlist 和预算、自己再模拟一遍，然后由 relayer 发一笔普通交易调用账户的 execute(批次, 签名)，gas 由 relayer 出。

为什么

sponsor 不是安全边界。它会拒绝不在 allowlist 里的账户，也会限制每日 gas 和单笔费用，但这些只保护 sponsor 自己的钱。agent 完全可以绕过 sponsor、自己付 gas 直接调用账户，链上规则照样生效。所以分析 agent 能动多少钱时，可以当 sponsor 不存在。（AA-DESIGN §4.0）

AA SDK 里还有另一条路径：ERC-4337 EntryPoint v0.8，由 bundler 打包、VerifyingPaymaster 代付。它在 SDK 里实现了，但这个 demo 不走它，验收也只覆盖 relayer 路径。

session export、24 小时过期、撤销#

默认情况下，session grant 把 session key 写进 root home，和 root key 放在一起、用同一个密码。直接把这个目录交给 agent 等于交出 root key。所以 AA SDK 0.1.5 加了一个只在链下运行的命令：

root 终端（root home 的环境）

MANTLE_AA_EXPORT_PASSWORD=<agent 的密码> \
  mantle-aa session export --agent trader --out ~/.mantle-meme-agent

它用 root home 的密码解开这把 session key，用新密码重新加密，写出一个只有这一个 agent profile 的 agent home，里面没有 root key 和 root profile。在这个目录里，agent simulate|exec 照常工作，所有账户和会话管理命令都会以“缺少 root profile”报用法错误。

  • 24 小时过期。mantle-aa 0.1.5 的 CLI 授予的 key 一律 24 小时后过期，没有选项可改，所以 policy init --expiry 只接受 24h。过期时间存在 Calibur 的 key 设置里，这是唯一的过期来源。
  • 撤销。人在 root 终端运行 mantle-aa session revoke --agent trader。一个管理批次同时做三件事：Calibur 删除这把 key，hook 把它标成墓碑（tombstone），MockUSD 对发射台的授权清零。墓碑不可清除，同一把 key 永远不能再被授予。

撤销之后 agent 和 autopilot 怎样停下：图 12 · 撤销流程

坑

session export 只肯写进一个新目录、空目录，或者同一个 agent 之前的导出。agent 用过的 home 里有 journal 和 autopilot 文件，它会拒绝。重新授权后要先换一个空的 agent home 再导出。

Calibur 的 nonce 通道和 hook 地址

relayer 路径用 Calibur 的 getSeq(key) 做 nonce：192 位的 key 加 64 位序号。SDK 和 sponsor 约定每把 session key 用自己的通道：lane = uint192(uint256(keyHash) >> 64)，root 用通道 0，sponsor 拒绝在 root 通道上提交 session 请求。这是约定，不是链上隔离：一把恶意 session key 绕过 sponsor 可以消耗别的通道的序号，后果只是拒绝服务。

Calibur 按 hook 地址的低 5 位决定调用哪些回调（验签后、UserOp 验证后、ERC-1271 后、执行前、执行后），所以 AgentPolicyHook 用挖出来的 CREATE2 salt 部署，低 5 位必须是 0x1f，SDK 授予 key 前会检查。

程序：TypeScript 库#

程序用库，不用 CLI。本项目所有 agent 交易都走同一段代码：在 agent home 里找到唯一的 agent profile，解密 session key，建一个 AgentSession，在发送锁下调用 session.exec。exec 内部就是图 5 的前四关；第五关在链上。

packages/sdk/src/executor.ts 和 packages/cli/src/cli.ts（节选，删掉了可选参数和错误诊断）

import { AgentSession, loadProfileSigner, RelayerExecutor } from "@0xwh1sker/mantle-aa-sdk";

// cli.ts：sponsor 的地址来自 MANTLE_AA_SPONSOR_URL，密码来自 MANTLE_AA_KEYSTORE_PASSWORD
const executor = new RelayerExecutor({ client, url, addresses });

// executor.ts：agent home 里的 session key → AgentSession
export function openAgentSession(o) {
  const { name, profile } = agentProfile(o.home, o.agent);
  const signer = loadProfileSigner(name, { home: o.home, password: o.password });
  return new AgentSession({ client: o.client, account: profile.account,
                            keyHash: profile.keyHash, signer, executor: o.executor });
}

// executor.ts：发送 = 锁 → 模拟、签名、交给 sponsor → 等回执 → 记 journal
export async function execute(o) {
  return withSendLock(o.home, async () => {
    const { hash } = await retrySponsorBusy(() => o.session.exec(o.calls));
    const receipt = await receiptOf(o.client, hash, 60_000);
    if (receipt.status !== "success") throw new ExecutionRevertedError(…); // 信回执，不信 sponsor
    appendJournal(o.home, tradesOf(receipt, o.launchpad, o.session.account, o.session.keyHash));
    return { hash, receipt };
  });
}

链上与库

合约：bonding curve 与截断#

MemeLaunchpad 既是代币工厂，也是每个代币的做市方。它没有 owner、不可升级、所有参数在构造时固定，只调用 MockUSD 和它自己部署的代币。价格来自 bonding curve：在虚拟储备上做恒定乘积，和 pump.fun 是同一个思路。

参数值含义
TOTAL_SUPPLY1,000,000,000 枚创建时全部铸给发射台
CURVE_SUPPLY800,000,000 枚曲线上能卖的部分；另外 2 亿枚留给将来的“毕业”，本版没有代码能动它
VIRTUAL_TOKEN_01,066,666,667 枚起点的虚拟代币储备 vT
VIRTUAL_QUOTE_0200 mUSD起点的虚拟报价储备 vQ
FEE_BPS100（1%）买卖双向收，向上取整；创作者拿一半（向下取整），协议拿余下的

买入时，扣掉手续费的净额进入 vQ，你拿到的代币是 vT − ⌈k / (vQ + net)⌉。除法一律向上取整，让舍入永远偏向曲线，所以任何状态下 vQ · vT ≥ k。起点价格约 1.875 × 10⁻⁷ mUSD 一枚；8 亿枚卖完时价格是起点的 16 倍，vQ 正好到 800 mUSD，一路买满大约花 606 mUSD（含手续费）。

最后一笔买入会被截断。如果你出的钱足以买下曲线上剩下的全部代币，合约只收刚好够的 amountInUsed，把剩下的代币全给你，状态变成 Completed。在 fork 上实测，买下最后 2,015,113.1 枚正好收了 6.060607 mUSD（其中手续费 0.060607）。

为什么

SDK 不靠链上截断。报价返回 completes = true 时，它先把 approve 和 buy 的 amountIn 都夹到 amountInUsed。原因有两个：hook 会拒绝超过剩余额度的 approve，而 AA SDK 的模拟按 buy 的 amountIn 扣额度。链上截断只兜底“报价之后、上链之前有人插队”的情况；这时没用完的授权留在发射台（受信 spender），下一次 approve 会覆盖它，撤销时清零。（DESIGN D29、§4.3.3）

生命周期只有 None → Trading → Completed。Graduated 在枚举里占位，但永远到不了。Completed 之后买和卖都会 revert（CurveAlreadyCompleted，CLI 退出码 40），持仓卖不掉。CLI 和 skill 统一这样说：“Curve completed; trading is disabled. This v1 launchpad has no migration path, so the position is stranded.” 是“搁浅”，不是“毕业”。

CREATE2：发币和首买放进一个批次#

createToken 用 CREATE2 部署代币，salt 是 keccak256(abi.encode(调用者, salt))。因为地址可以离线算出来，CLI 能在代币还不存在时就把“发币 + approve + 买入”放进同一个批次。

关键在于 Calibur 对批次里的每个调用分别调 hook。buy 的 beforeExecute 要读 balanceOf(预测地址)，这时第一个调用已经把代币部署好了，所以读得到。这一点在 0.1.0 的 fork 测试里走完整 sponsor 路径验证过，两笔交易的备用方案没有用上。

手续费：每笔交易的 1% 在合约里分账，creatorFees[token] 记创作者那一半。claimCreatorFees(token) 只有创作者能调，钱付给调用者本人；在这里创作者就是账户，所以 agent 领手续费是钱流进账户。claimProtocolFees() 谁都能调，但钱只付给构造时固定的 treasury。

为什么

成本只能来自本地 journal。链上的 Trade 事件只记账户，分不清同一账户的两个 session；所以“一个账户同时只有一个活跃 session”是支持范围，journal 丢了，那个代币的成本就是 null（未知），autopilot 不会去管它。（DESIGN D33、R-8）

坑

部署的 Calibur 在 session 调用失败时只抛一个光秃秃的 CallFailed()，发射台的 revert 原因丢了。executor.ts 的 diagnoseFailure 会先看有没有明确的 revert 数据；没有时才按合约的检查顺序重读链上状态来推断（未知代币 / 曲线已完成 → 余额 → 滑点）。这是启发式：推断不出就原样返回 AA 的错误（exit 30）。

journal 的一行长什么样，写到一半崩溃了怎么办

每笔确认的交易，回执里每一条属于这个发射台、trader 是这个账户的 Trade 日志写成一行 JSON：

<agentHome>/meme/journal.jsonl 的一行（字段来自 packages/sdk/src/journal.ts，值是占位符）

{"keyHash":"0x…","txHash":"0x…","token":"0x…","side":"buy",
 "quotePulled":"3000000","tokens":"15608217968123367985416564","fee":"30000",
 "blockNumber":"…","correlationId":"…"}

买入的 quotePulled 含手续费，卖出的是扣费后到手的数。进程在追加一半时崩溃，最后一行可能没有换行。读的时候，不完整的最后一行被跳过，那个代币的成本变成 null；下一次追加（在发送锁下）先把它切掉，如果它其实是完整记录、只差一个换行，就补上换行保留。别处的坏行一律大声报错，不会被悄悄跳过。

autopilot：打新的确定性程序#

“打新”就是在新币刚上线时用固定金额买入，涨到目标后卖出。这件事交给一个独立的 daemon，而不是 LLM：它按策略文件机械地执行，LLM 只负责把你的话写成策略、复述给你、启动和停止它、事后解释它做了什么。

strategy.json（“每个新币 3U，涨 50% 卖一半，最多拿 30 分钟”）

{
  "entry": { "amountPerToken": "3", "maxAgeSeconds": 60, "keywords": [], "excludeOwn": true,
             "maxOpenPositions": 10, "maxEntryPriceMultiple": 2 },
  "exit":  { "takeProfitPercent": 50, "takeProfitSellPercent": 50,
             "maxHoldMinutes": 30, "stopLossPercent": null },
  "slippagePercent": 3
}

daemon 的循环很简单：watcher 看到 TokenCreated，按“发现时的年龄、关键词、不是自己发的、价格不超过发射价的 2 倍、持仓数”过滤；再看剩余额度和余额是否都够；重新报价后买入。之后，持仓代币每出现一笔 Trade（以及每 10 秒一次 tick），就用本地曲线模型算“卖掉 50% 能净拿多少”，和这部分的 journal 成本比：达到 +50% 就用 quoteSell 复核后卖出，每个仓位只止盈一次；到了最长持有时间就把剩下的全卖掉。

  • 链上时间。所有时间都用最新区块的时间戳：发现时的年龄、买入时刻（那个区块的时间）、最长持有。在 anvil fork 上用 evm_increaseTime + evm_mine 就能测最长持有，不用真等 30 分钟。
  • pid 锁。autopilot start 先拒绝已在运行的 daemon（exit 44），再启动一个分离的子进程。daemon 在发送锁下独占创建 pid 文件，两个同时启动的 daemon 只有一个能赢。
  • 恢复。每笔 autopilot 交易发送前，先把 {token, 原因, 唯一 id} 作为 pending 写进 state.json；execute 把这个 id 作为 correlationId 写进 journal。daemon 若在“已上链、未存盘”时死掉，重启时只认 journal 里带同一个 id 的记录。手动交易不带 id，永远不会被误认。
  • 撤销感知。空闲的 daemon 不发交易，也就不会撞上 exit 13，所以每个 tick 都直接读链上：key 还注册着吗、过期了吗、hook 上 revoked 了吗。任何一项不对就记 session_ended 并退出。
  • Telegram 推送。设置了 bot token 和 chat id 时，daemon 用 Bot API 的 sendMessage 按顺序推送模板消息，不经过 LLM。每条 10 秒超时，失败记一个 error 事件（token 会被抹掉），从不影响交易。

它写的文件都在 <agentHome>/meme/autopilot/：pid、strategy.json、state.json、events.jsonl、daemon.log。

skill 和它的规则#

OpenClaw 的 skill 就是一个带 frontmatter 的 SKILL.md 目录。这里只有一个 skill，没有插件：skill 交给 agent 的每件事都是一条 mantle-meme 命令。frontmatter 要求 mantle-meme 可执行文件和四个环境变量都在，否则 skill 不加载。正文是命令表、JSON 结果的形状、每个退出码该怎么说，以及下面这些规则。最后一列是关键：这条规则有没有链上兜底。

Docker 容器#

OpenClaw 跑在一个长期运行的容器里，镜像是固定 digest 的 OpenClaw 2026.10.6，构建时把本仓库的 mantle-meme 装进去。OpenClaw 自带的沙箱是关的，由容器来隔离凭据：它决定 agent 拿得到哪些钥匙（第 5 节）。容器只挂三个目录：

从不挂载 ~/.mantle-aa、root home、~/.openclaw、~/.ssh 和 docker socket。容器的环境变量里有 agent home 的路径、agent 的密码（docker inspect 看得到，所以只用于测试网）、指向 host.docker.internal 的 RPC 和 sponsor 地址、Telegram 的 bot token 和 chat id。

为什么需要 launcher#

OpenClaw 2026.10.6 在 Linux 上把 exec 工具启动的每个命令都放在一个 child subreaper 下面，而且没有开关：命令返回时，它留下的进程全被杀掉；一轮对话结束时，还在跑的也被停掉。autopilot start 启动的 daemon 正是这种“留下的进程”，直接从 agent 启动，几毫秒内就没了。

解决办法没有改 mantle-meme 本身，而是在镜像里加了两个小文件：

  • launcher.mjs 是容器的主进程，跑在镜像自带的 tini 下面，在 OpenClaw 的进程树之外。它监听容器内的 /tmp/mantle-meme-launcher.sock（不在挂载卷上），只接受 autopilot start --strategy <file> [--agent <name>] [--json]，用参数数组（不经 shell）运行真正的 CLI，把 stdout、stderr 和退出码原样转回去。
  • mantle-meme.mjs 是 agent 的 PATH 上那个 mantle-meme。除了 autopilot start，所有命令都在同一进程里直接跑真 CLI；autopilot start 连同当前目录发给 launcher。

这样 daemon 是 launcher 的后代，活过这一轮对话；输出和退出码与直接调用一致（第二次 start 照样是 44）。

坑

daemon 继承的是容器的环境，不是触发它的那次 docker exec 的环境。想调 MANTLE_MEME_AUTOPILOT_TICK_MS 之类的变量，要在容器启动时设。

gateway、模型、RPC relay、代理#

  • gateway。demo-up.sh 给容器设 MANTLE_MEME_GATEWAY=1，launcher 就把 openclaw gateway --bind loopback 作为子进程启动，容器跟着 gateway 活。Telegram 通道由 config set 写入：dmPolicy: "allowlist"、allowFrom 只有你的 chat id、groupPolicy: "disabled"，bot token 从环境变量 TELEGRAM_BOT_TOKEN 读，不落文件。别的 id 发来的私聊被静默丢弃。
  • 一个 bot 两用。gateway 用长轮询收消息，autopilot 用同一个 bot 的 sendMessage 推送。所以同一时间只能有一个进程在轮询这个 bot，否则会看到 409 Conflict。
  • 模型。模型登录由 OpenClaw 自己管，存在 OpenClaw 状态目录里。有两条路：带 OpenClaw 插件的提供方用 models auth login --provider …；自定义的 OpenAI Responses 兼容端点先用 config set models.providers.… 配好，再用 models auth paste-api-key 在提示符里输入 key（不上命令行）。demo-up.sh 启动后跑 models status --check，不通过就停下；但这个检查不发请求，key 或 URL 写错也能过，只有一轮真实对话才能证明提供方接受这个 key。
  • RPC relay。公共的 Mantle Sepolia RPC 会拒绝突发请求（rate limit），而 portfolio 恰好会并行发很多读请求。scripts/rpc-relay.mjs 在 127.0.0.1:8547 转发，同时最多 4 个，被限流的请求重试；它不记 URL 和请求体。
  • 代理。在只能经代理访问 Telegram 的网络里，demo-up.sh 把当前 shell 的 https_proxy 改写成 host.docker.internal 传给容器，并设 NODE_USE_ENV_PROXY=1；OpenClaw 和 autopilot 的推送都走它。DEMO_PROXY= 可以关掉。
坑

容器重启后，OpenClaw 会接着跑被中断的那一轮对话（bot 会说 “continuing your interrupted request”）。所以只在 bot 空闲时运行 demo-down.sh。

3合起来：一个系统怎样运作#

关键流程

命令买入#

你说“买 2U 的 DOGE9”。按 skill 的规则，agent 先跑 quote，再跑 buy，不再问你确认（在 policy 内的请求直接执行）。真正的工作在 CLI 和 AA SDK 里：

  1. CLI 解析符号（扫最新 1000 个代币，精确、大小写不敏感），确认曲线还在交易，否则直接 exit 40 / 42。
  2. 调链上的 quoteBuy。会买空曲线就夹到 amountInUsed。minOut 是报价减 5%，deadline 是最新区块时间加 300 秒（hook 允许的上限是 600）。
  3. 组成批次 [approve(MockUSD → 发射台, 金额), buy(token, 金额, minOut, deadline, 账户)]，拿发送锁。
  4. AA SDK 在本地按 hook 规则逐条预检并 eth_call，通过后用 session key 签名，发给 sponsor。
  5. sponsor 鉴权、再模拟、预留费用，relayer 发交易。链上 Calibur 验签，hook 检查每个调用，发射台成交。
  6. CLI 等回执：status 必须是 success，不信 sponsor 的一面之词。然后把这笔交易自己的 Trade 日志写进 journal，释放锁，返回 JSON。
为什么

sponsor 对同一个账户同时只接受一个在途请求，再来一个就回 SPONSOR_BUSY。autopilot 和你的手动命令共用一个账户，发送锁让它们排队，而不是在 sponsor 那里撞车。验收里专门测过：同时发起的 autopilot 买入和手动买入都成功，用户看不到 SPONSOR_BUSY。（DESIGN D20、§9.1 第 8 项）

5安全模型与信任边界#

如果 agent 被 prompt injection 了，最坏会发生什么？

先说结论：把 agent 当成已经被攻破来分析。agent 的每个决定都来自模型，而模型读的是链上谁都能写的代币名称、命令输出和你的消息。能约束一个被攻破的 agent 怎样动钱的，只有链上合约；容器做的是另一件事，让它从一开始就拿不到 root key。

链上强制的#

  • Calibur + AgentPolicyHook：白名单、额度、inventory、收款人、deadline 窗口、过期、撤销墓碑（逐项检查见 图 4）。非 admin 的 key 不能调用账户自己，hook 拒绝以它自己为目标的调用，所以 session key 改不了 policy；hook 对 session key 的 ERC-1271 签名一律拒绝。
  • 发射台：没有 owner、没有升级、没有管理员提款路径；只从 msg.sender 拉钱；只交易自己注册的代币；卖出要么足额要么回滚。这些是 AA SDK 对“受信发射台”的接口要求（AA-DESIGN §4.4），hook 自己验证不了，是人把发射台写进 policy 时做的信任声明。

AA SDK 的承诺是：一把被攻破的 session key，造成的报价资产净流出不超过它的额度（按成本算）；只能卖自己买到的数量；改不了 policy、签不了 ERC-1271、撤销后回不来。它不保证持仓的市值：被攻破的 key 可以用极低的 minOut 把自己的持仓全卖掉，按市值算的损失可以远超额度。

只是 skill 规则的#

“先报价”“启动 autopilot 前要你说是”“不打印环境变量”都只靠模型自觉。一个读到恶意代币名称的模型可能违反其中任何一条。比如它可能不等你确认就启动 autopilot，或者高价买进别人拉起来的币；后者在额度内是合法交易，链上不会拦。

安全

公共测试网上任何人都能发币，代币的名称、符号、描述都是不可信输入，会出现在 list、info、autopilot 的推送和 agent 的上下文里。autopilot 本身是确定性程序，名称只影响关键词过滤；但 LLM 会读到它们。

容器里的凭据#

容器是凭据隔离边界：root home 从不挂进去，agent 拿不到 root key。它不限制 agent 手里那把 session key 能做什么，那是链上的事。另外，agent 的 exec 工具在容器里不受沙箱约束，容器里有的东西它都读得到：agent 的密码（因此等于拿到 session key 本身）、bot token、OpenClaw 的模型登录。容器可以上网，所以一个被攻破的 agent 能把它们发出去。后果分别是：session key 在额度内被滥用（撤销即止），bot 被冒用（换 token），模型额度被盗用。

安全

这是一个 POC：合约未经审计（0.1.0 有一次合约评审检查点，结论 PASS，最终的独立安全评审在 0.1.4），只在 Mantle Sepolia 上用测试币。relayer 和 market-sim 的钱包只放测试网金额。不要把这里的任何配置搬到主网。

7已知限制#

它现在做不到什么？哪些地方会让你意外？

  • 没有止损。策略里的 stopLossPercent 是预留字段，非 null 就是用法错误。价格一路跌，autopilot 只会在最长持有到期时卖。
  • 没有防夹（sandwich）保护。滑点只限制单笔输出；maxEntryPriceMultiple 只跳过明显被拉过的新币，不是防夹。合约层面也不保护成交价格。
  • 曲线卖完就搁浅。Completed 之后买卖都停，本版没有迁移到 AMM 的路径。
  • 最长持有会卖掉这个 session 在该代币上的全部 inventory，包括你手动买的那部分。autopilot 只管它自己开的仓，但卖的时候按 inventory 算。
  • 公共 RPC 的限制。公共 Mantle Sepolia RPC 会拒绝突发请求（rate limit exceeded），所以演示里所有请求都经过本地 relay；它还是负载均衡的，偶尔落后一个块（requested block is above the latest consensus block），这时 autopilot 可能把新币记成 skipped too_old。
  • 一个账户只支持一个活跃 session（成本、portfolio、autopilot 都按这个假设）。链上 inventory 仍然按 key 分开记。
  • 24 小时一到就得重新授权、重新导出，而且要导出到一个空的 agent home。
  • CR-02：极大的买入预算（≳1e73 base units）会在截断前溢出并安全回滚。合约已部署不可改，SDK 的夹紧让正常金额碰不到它，留到下一个发射台版本。

术语表#

EOA
外部账户：一把私钥对应的普通地址，本身没有代码。
EIP-7702
让 EOA 把代码委托给一个合约实现的交易类型（type-4）。地址和私钥不变。
Calibur / CaliburEntry
Uniswap 的 7702 账户实现（v1.1.0）。支持多把 key、每把 key 绑定 hook 和过期时间。
root key
根密钥：EOA 自己的私钥，账户的 admin，不受 hook 约束。只在人的 root 终端里。
session key
会话密钥：root 授予 agent 的非 admin key，每个调用都过 AgentPolicyHook，24 小时过期。
AgentPolicyHook
AA SDK 的链上 policy 合约。单例、不可升级，按 (keyHash, account) 存 policy、已花额度、inventory 和状态。
policy / ruleKind
一把 session key 的权限：白名单、额度、受信 spender、deadline 窗口。ruleKind 决定对一个调用的参数查什么：ERC20_APPROVE、LAUNCHPAD_BUY、LAUNCHPAD_SELL、NONE。
报价资产（quote asset）
policy 里有额度的 ERC20，这里只有 MockUSD（mUSD，6 位小数，谁都能铸的测试币）。
inventory
库存：hook 记的“这把 key 通过买入得到多少某代币”，也是它最多能卖多少。
墓碑（tombstone）
hook 上 revoked = true 的标记，不可清除；同一把 key 永远不能再被授予。
SignedBatchedCall
session key 签的一组调用，带截止时间和指定的 executor（relayer）。
sponsor / relayer
mantle-aa sponsor serve：鉴权、模拟、记账的代付服务；relayer 是它用来发交易、付 gas 的热钱包。
bundler / paymaster
ERC-4337 那条路径：bundler 打包 UserOp 交给 EntryPoint v0.8，VerifyingPaymaster 代付。SDK 支持，本 demo 不用。
root home / agent home
MANTLE_AA_HOME 指向的密钥目录。root home 有 root key；agent home 是 session export 导出的，只有一把 session key。
bonding curve
联合曲线：价格由已卖出量决定的做市方式。这里是虚拟储备上的恒定乘积。
amountInUsed
一笔买入实际被收取的报价金额。截断时小于你给的 amountIn。
Completed / 搁浅
曲线卖完后的状态。买卖都停，持仓卖不掉。
CREATE2 / salt
可预测地址的合约部署方式。发射台把调用者和 salt 一起哈希，别人抢注不了你的地址。
发送锁（send lock）
<agentHome>/meme/send.lock：同一时间只让一个进程为这个账户发送。
journal
<agentHome>/meme/journal.jsonl：这个 session 每笔确认交易的成交记录，成本的唯一来源。
correlationId
autopilot 发送前生成的交易 id，写进 journal，用于崩溃后对账。
autopilot daemon
按策略文件自动打新和止盈的后台进程，不含 LLM。
链上时间
最新区块的时间戳。autopilot 所有时间判断都用它。
launcher
容器的主进程，替 agent 启动 autopilot，让 daemon 不在 OpenClaw 的进程树里。
child subreaper
Linux 进程属性：孤儿进程归它回收。OpenClaw 的 exec 工具用它来清理命令留下的进程。
gateway / skill
OpenClaw 的常驻服务（接 Telegram 等通道）；skill 是一个 SKILL.md 目录，教模型用某个工具。
market-sim
不含 LLM 的市场模拟器：几个自付 gas 的 EOA 发币、买卖、拉盘。
